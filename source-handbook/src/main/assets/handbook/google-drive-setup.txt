Google Drive setup (#1496, #1677)

Candela can connect to a user's Google Drive and read the **Google Docs,
PDFs, EPUBs and text files they choose** as a Browse source, with real
chapters (EPUB spine, PDF headings / page batches) and read-aloud like any
other book. Google Docs are read natively (exported to text), which the
system file picker can't do. With no setup at all you can still open a
single Drive file through Android's system picker (see docs/faq.md, "Does
Candela read files from Google Drive?").

The Drive chip only appears when the build has an OAuth client id. This
doc lists what to register once to turn it on. Every value has an
empty-string BuildConfig default, so **the app builds and CI stays green with
no credentials**. Without them the chip is hidden (no client id), or it says
file choosing isn't set up (client id but no Picker key).

---

The load-bearing scope decision: drive.file only

Candela requests exactly one scope:

drive.file is a non-sensitive scope: the app sees only the files the
user picks in the Google Picker, never the rest of their Drive. We
deliberately do not request drive.readonly or drive. Those are
restricted scopes: they trigger Google's app-verification wall and
possibly an annual, paid CASA security assessment, which is too much for
an open-source app.

The accepted trade-off: Candela can't list your whole Drive. It sees only
what you pick, and that is the privacy point.

1 · Google Cloud console (one-time, JP)

All of this is in one Google Cloud project. Its project number is used
in step 1.6.

Enable APIs (APIs & Services → Library):
Google Drive API
Google Picker API
OAuth consent screen (APIs & Services → OAuth consent screen, or
   Google Auth Platform → Branding / Audience / Data access):
User type External.
App name "Candela", support email, developer contact email.
App domain / home page https://candela.techempower.org, privacy policy
     https://candela.techempower.org/privacy.
Authorized domain: techempower.org.
Scopes → add …/auth/drive.file and nothing else.
Publish app (Audience → "In production"). A non-sensitive scope
     doesn't need Google's review. While it stays in "Testing", only the test
     users you list can sign in (up to 100), and their refresh tokens expire
     after 7 days.
OAuth client (Credentials → Create credentials → OAuth client ID):
Application type iOS (recommended). It's a PKCE public client with
     no secret, and its redirect is the reversed-client-id scheme Candela
     registers. Bundle ID: org.techempower.candela (Google only uses it to
     label the client). No App Store ID or team ID is needed.
Alternative: type Android, package org.techempower.candela, plus
     the SHA-1 of the signing cert. You then must turn on *Advanced
     settings → Enable custom URI scheme*. Google disables custom schemes for
     Android clients by default, and without it the consent screen refuses
     the redirect. iOS avoids that setting and works for every signing key
     (sideload APK and Play build alike).
Copy the client ID (<n>-<hash>.apps.googleusercontent.com).
Picker API key (Credentials → Create credentials → API key):
Restrict it: Application restrictions → Websites, with referrer
     https://candela.techempower.org/*.
API restrictions → Restrict key → Google Picker API (and Google Drive
     API if the console asks for it).
This key is public by design: every web page that uses the Picker ships
     its key. The referrer restriction is what protects it.
(Optional) If the Picker ever reports an origin error, create a **Web
   application** OAuth client in the same project with authorized JavaScript
   origin https://candela.techempower.org. Candela never uses its id. It
   only registers the origin with the project.
Project number: Dashboard / Project settings → Project number (a
   long number, not the project ID). This is the Picker appId. It must be
   the project that owns the OAuth client, or picking a file won't grant
   Candela access.

Redirect URIs (nothing to type)

The consent screen returns to the reversed client id:

app/build.gradle.kts derives this scheme from GOOGLEOAUTHCLIENT_ID and
registers it in the manifest through the googleOAuthRedirectScheme
placeholder. GoogleDriveOAuthConfig.redirectUri derives the same value at
runtime, so the two can't drift. iOS and Android client types accept this
redirect automatically, and there is no redirect-URI field to fill in. The
old candela://oauth/googledrive redirect is only a fallback for a
non-standard client id.

The Picker page returns to candela://oauth/googledrive/picked, which the
existing manifest filter covers.

---

⚠️ Security note — no secret needed (unlike Notion)

Google's installed-app flow is a PKCE public client. The token exchange
authenticates with a one-time code_verifier (RFC 7636), not a client
secret. Google documents the secret as *"not applicable to requests from
clients registered as Android, iOS, or Chrome applications."* So with the
recommended iOS or Android client type, no secret ships in the APK, which
is better than the Notion flow (a confidential client that has to ship its
secret).

The Picker API key and project number are public values, not secrets.

The Picker page gets the access token in the URL fragment. Browsers
never send the fragment to a server, and the page wipes it from the address
bar and history as soon as it loads. The token is drive.file-scoped and
expires within an hour.

---

How it works

Connect Google Drive (Browse → Google Drive chip) →
   GoogleDriveOAuthManager.beginConnect() creates a CSRF state nonce and
   a PKCE code_verifier, stores both encrypted (they survive process
   death), and opens the authorize URL in a Chrome Custom Tab.
Google redirects to com.googleusercontent.apps.<n>:/oauth2redirect?code=…&state=…
   (or ?error=access_denied on cancel, which is handled without a crash).
   MainActivity verifies the state, exchanges the code with the stored
   verifier, and saves the access token, refresh token and expiry in the
   encrypted storyvox.secrets store. The google-drive source is turned on
   automatically.
Choose from Google Drive opens docs/drive-picker.html
   (https://candela.techempower.org/drive-picker.html) in a Custom Tab. The
   Picker shows Docs, PDFs, EPUBs, text files and folders, with multi-select
   and shared drives. Picking is the grant: after that, drive.file
   lets Candela read those files. The page links back to
   candela://oauth/googledrive/picked, and Browse lists the files again.
The source lists what you've granted (GET /drive/v3/files) and reads:
Google Docs via …/export?mimeType=text/plain, as one chapter;
text files via ?alt=media, as one chapter;
EPUBs via ?alt=media, then :source-epub's parser, one chapter per
     spine item;
PDFs via ?alt=media, then :source-pdf's PdfBox text layer (with OCR
     fallback), with chapters split by heading or by page batch.
   Parsed books are memoised per fileId@modifiedTime. Downloads over
   100 MiB are refused.
Tokens: the source refreshes the access token when it is within
   2 minutes of expiry, and on a 401/403 it refreshes once and retries.
   invalid_grant (a revoked or expired refresh token) clears the session,
   and the chip goes back to Connect.
Disconnect (the chip's ＋ button, or the empty state) revokes the
   token at oauth2.googleapis.com/revoke, which removes Candela from the
   user's Google Account → Security → Third-party access, and then wipes the
   local session.

Folders: you can pick folders. Whether picking a folder grants the files
inside it under drive.file depends on Google, so the reliable path is to
pick the files themselves (multi-select). Anything granted shows up in the
list.

Data-safety lock-step

This doesn't change Candela's Play Data-Safety posture. The token is the
user's own credential, content goes from Google to the device directly, the
Picker runs on Google's servers in the user's browser, and Candela shares
nothing. The Drive rows added in #1496 still apply:

docs/privacy.md — §2.2 backends + §4 third-party table (Google Drive row).
docs/data-safety-checklist.md — §C sharing note (#1496 clarification).
docs/play-store-walkthrough.html — §IV "API keys & tokens" row.
